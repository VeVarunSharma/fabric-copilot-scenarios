# Executive briefing runbook

## Goals

- Show how GitHub Copilot shortens analytics delivery time without removing governance.
- Connect Microsoft Fabric delivery work to measurable customer outcomes.
- Give leaders a clear view of which tasks remain human-owned.

## Best fit

Use this runbook for executive sponsors, transformation leads, data platform owners, and security stakeholders who need the story before the deep technical detail.

## Flow

1. Open with the business problem and the cost of manual analytics delivery.
2. Show the [architecture](../architecture.md) and explain the end-to-end path.
3. Highlight the work Copilot removes: scaffolding, draft documentation, repetitive model and SQL setup, and initial governance checklists.
4. Show one prompt pack and one placeholder visual rather than a long build walkthrough.
5. Close with adoption guardrails, review ownership, and next-step recommendations.

## Roles

- Executive storyteller: frames business value and transformation priorities.
- Fabric lead: explains the analytics flow and trust model.
- GitHub lead: explains governance, review, and security controls.
- Moderator: keeps the session tied to business outcomes.

## Setup

- Prepare the [architecture placeholder](../images/placeholders/architecture-placeholder.svg).
- Pre-select a persona path from [persona paths](../persona-paths.md).
- Choose one scenario prompt that best matches the customer priority.
- Keep [data safety guidance](../governance/data-safety.md) available for questions about synthetic data and screenshots.

## Checkpoints

- The audience can describe the end-to-end flow in plain language.
- The audience can name at least three types of work Copilot eliminates.
- The audience understands that governance settings live in GitHub and Fabric administration, not just in files.
- The audience agrees on a likely pilot use case.

## Exit criteria

- A named business outcome is selected.
- A target persona or team is identified for a follow-on working session.
- Governance owners know which settings and approvals must be validated outside the repository.
