# Data and AI accelerator runbook

## Goals

- Align strategy, architecture, delivery, and governance in a single customer motion.
- Show how Copilot supports both immediate productivity gains and longer-term operating model change.
- Produce a practical adoption backlog that spans people, process, and platform.

## Best fit

Use this runbook for customers who want an end-to-end transformation conversation that covers data engineering, analytics, governance, and enablement together.

## Flow

1. Start with the transformation goal and the target operating model.
2. Use the [architecture](../architecture.md) to anchor the technical story.
3. Walk the room through selected persona paths.
4. Review prompt packs that map to the highest-value work items.
5. Discuss governance, security, deployment, and change-management implications.
6. Close with a phased adoption backlog and ownership model.

## Roles

- Executive sponsor
- Analytics architect
- Fabric delivery lead
- GitHub platform lead
- Security or governance representative

## Setup

- Review [persona paths](../persona-paths.md).
- Review [Fabric deployment guidance](../governance/fabric-deployment.md).
- Review [GitHub Enterprise guidance](../governance/github-enterprise.md).
- Use [prompt library entry points](../../prompts/README.md) for each role.

## Checkpoints

- The customer can map a business goal to at least one persona path and scenario prompt.
- The room agrees where Copilot should help first and where manual controls remain strongest.
- Deployment, security, and data-safety prerequisites are understood.
- A practical next-step plan exists for both builders and governance owners.

## Exit criteria

- A prioritized adoption backlog exists.
- Named owners are identified for technical pilot, governance validation, and enablement.
- The customer knows which external settings must be configured before a live rollout.
